# 方案调研与差异化分析

> 本文对应任务要求 ②（检索现成智能体方案）与 ③（分析差异 + 个性化）。
> 结论：现成方案能解决"把笔记发布出去"这一段，但都解决不了"**按学科知识形态自动重构内容**"这一段 —— 这正是我这个项目的个性化价值所在。

## 一、我的真实需求（问题定义）

不要泛泛地说"整理笔记"，我的问题是**具体的四重困境**：

1. **形态异构**：我 4 门课的笔记知识形态完全不同 —— 毛概是对答、计网是公式计算、英语是长语料、C 语言是代码，但原始笔记把它们**全部拍平成同一种无层级列表**。
2. **语法损坏**：一路敲下来，`#` 后不带空格，标题层级全部失效；公式被写成 `10的七次方`、`2*10的八次方`，复制后上标丢失。
3. **无法检索**：考前想按知识点查找，只能 Ctrl+F 翻列表。
4. **通用工具不理解学科差异**：任何"通用笔记发布/整理工具"都只会把我的四种内容一视同仁。

**一句话**：我要的不是"把我的笔记搬上网"，而是"**让每一科笔记按它自己的知识形态被重新组织**"。

## 二、检索到的现成方案

我从四个主流来源检索了可用的现成方案：

### 来源 A：智能办公集成平台（WorkBuddy / 千问办公 / 豆包）

| 方案 | 能做什么 | 与本需求的关系 |
|---|---|---|
| WorkBuddy 文档技能 | 生成/排版专业文档（研报、公文、合同） | 强在**单篇文档的写作与美化**，不是"批量笔记的分学科重构" |
| WorkBuddy 知识库 | 资料沉淀、语义检索 | 强在**检索**，但不负责把异构笔记**重构**成结构化形态 |
| 豆包技能广场 | 总结、翻译、摘要类技能 | 强在**一次性摘要**，无"学科感知的分类处理"，也无持久化站点 |
| 千问办公 | 文档问答、表格处理 | 强在**问答**，同样不做"把笔记重构并发布成站点" |

**共同点**：它们都是**通用语义能力**，不理解"毛概=问答、计网=公式"这种**学科形态差异**。

### 来源 B：GitHub 上的现成项目

| 项目 | 定位 | 与本需求的关系 |
|---|---|---|
| `jobindjohn/obsidian-publish-mkdocs` | 把 Obsidian 笔记发布到 GitHub Pages | **我最初就是用的这个模板** —— 它解决"发布"，不解决"整理" |
| `ObsidianPublisher/obsidian-mkdocs-publisher` | Obsidian → MkDocs 自动发布 | 同上，纯发布管道 |
| `Jackiexiao/foam-mkdocs-template` | Foam/MkDocs 模板 | 同上，纯模板 |
| `KosmosisDire/obsidian-webpage-export` | 导出 Obsidian 库为 HTML | 同上，导出工具 |
| `lyz-code/blue-book` | 大型知识库示范 | 展示**手工**维护 nav 的复杂度，未自动化整理 |

**共同点**：GitHub 这一类的共性非常清晰 —— **它们全是"发布/导出"管道，没有一个做"内容结构化重构"**。

## 三、差异分析：现成方案 vs 我的真实需求

| 需求维度 | 现成方案的表现 | 差距 | 我的个性化补法 |
|---|---|---|---|
| **异构内容识别** | 一视同仁地搬运 | ❌ 完全缺失 | 在脚本里定义**学科档案表**（qa/calc/language/code 四型），每科走不同处理器 |
| **Markdown 语法修复** | 不处理 | ❌ 缺失 | `fix_markdown_headings()` 自动补空格，恢复标题层级 |
| **公式还原** | 不处理 | ❌ 缺失 | 中文口语 → 科学计数法（`10的七次方`→`10^(7)`） |
| **结构重构** | 原样搬运 | ❌ 缺失 | 毛概→卡片、计网→题目分离、C 语言→代码块 |
| **发布成站点** | ✅ 现成且成熟 | 已满足 | **直接复用** Obsidian+ MkDocs 模板这一层 |
| **个性化流程** | 无 | ❌ 缺失 | 学科档案 + 分类处理器 = 完全贴合我 4 门课的定制流程 |

**核心结论**：
> 现成方案解决的是**"最后一公里"（发布）**，而我的痛点其实在**"前面九公里"（整理重构）**。
> 我做的事 = **保留成熟的发布层** + **自研缺失的整理层**，形成一个学科感知的笔记整理智能体。

## 四、我的方案为什么是"个性化"的

不是"功能更多"，而是**换个人来用就完全不适用**：

1. **数据个性化**：学科档案表里写死的是**我的 4 门课**（毛概、计网、英语、C 语言），换个专业就得重配。
2. **流程个性化**：每科的处理策略来自**我实际的笔记形态**（毛概确实是对答、计网确实是算题）。
3. **痛点个性化**：公式上标丢失、`#` 缺空格，都是**我这套笔记特有的损坏模式**，通用工具不会去修。
