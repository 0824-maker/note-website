    方案调研与差异化分析¶

    本文对应任务要求 ②（检索现成智能体方案）与 ③（分析差异 + 个性化）。 结论：现成方案能解决"把笔记发布出去"这一段，但解决不了"按学科知识形态自动重构内容"与"本地智能决策"这两段 —— 这正是我这个项目的个性化价值所在。

    一、我的真实需求（问题定义）¶

    不要泛泛地说"整理笔记"，我的问题是具体的四重困境：

    1. 形态异构：我 4 门课的笔记知识形态完全不同 —— 毛概是对答、计网是公式计算、英语是长语料、C 语言是代码，但原始笔记把它们全部拍平成同一种无层级列表。
    2. 语法损坏：一路敲下来，# 后不带空格，标题层级全部失效；公式被写成 10的七次方、2*10的八次方，复制后上标丢失。
    3. 无法检索：考前想按知识点查找，只能 Ctrl+F 翻列表。
    4. 通用工具不理解学科差异：任何"通用笔记发布/整理工具"都只会把我的四种内容一视同仁。

    一句话：我要的不是"把我的笔记搬上网"，而是"让每一科笔记按它自己的知识形态被重新组织"，并且这个整理过程要由 AI 智能体自动完成。

    二、检索到的现成方案¶

    我从四个主流来源检索了可用的现成方案：

    来源 A：智能办公集成平台（WorkBuddy / 千问办公 / 豆包）¶

    方案 能做什么 与本需求的关系
    WorkBuddy 文档技能 生成/排版专业文档（研报、公文、合同） 强在单篇文档的写作与美化，不是"批量笔记的分学科重构"
    WorkBuddy 知识库 资料沉淀、语义检索 强在检索，但不负责把异构笔记重构成结构化形态
    豆包技能广场 总结、翻译、摘要类技能 强在一次性摘要，无"学科感知的分类处理"，也无持久化站点
    千问办公 文档问答、表格处理 强在问答，同样不做"把笔记重构并发布成站点"

    共同点：它们都是通用语义能力，不理解"毛概=问答、计网=公式"这种学科形态差异。

    来源 B：GitHub 上的现成项目¶

    项目 定位 与本需求的关系
    jobindjohn/obsidian-publish-mkdocs 把 Obsidian 笔记发布到 GitHub Pages 我最初就是用的这个模板 —— 它解决"发布"，不解决"整理"
    ObsidianPublisher/obsidian-mkdocs-publisher Obsidian → MkDocs 自动发布 同上，纯发布管道
    Jackiexiao/foam-mkdocs-template Foam/MkDocs 模板 同上，纯模板
    KosmosisDire/obsidian-webpage-export 导出 Obsidian 库为 HTML 同上，导出工具
    lyz-code/blue-book 大型知识库示范 展示手工维护 nav 的复杂度，未自动化整理
    344303947/SuperNote 本地 AI 笔记管理（FastAPI + AI 自动分类/标签） 有 AI 自动分类思路，是我的重点参考方案；但其分类是自由打标签，无"学科→章节"固定体系，无学科感知整理，无站点发布链路

    共同点：发布类项目不做内容重构；带 AI 的项目分类是"自由标签"，不是"学科→章节"的固定体系，也没有"整理 + 摘要 + 发布"的完整链路。

    三、差异分析：现成方案 vs 我的真实需求¶

    需求维度 现成方案的表现 差距 我的个性化补法
    异构内容识别 一视同仁地搬运 ❌ 完全缺失 在脚本里定义学科档案表（qa/calc/language/code 四型），每科走不同处理器
    Markdown 语法修复 不处理 ❌ 缺失 fix_markdown_headings() 自动补空格，恢复标题层级
    公式还原 不处理 ❌ 缺失 中文口语 → 科学计数法（10的七次方→10^(7)）
    结构重构 原样搬运 ❌ 缺失 毛概→卡片、计网→题目分离、C 语言→代码块
    语义级章节摘要 无（最多一次性摘要） ❌ 缺失 AI 层：本地大模型（Ollama + qwen2.5）逐章生成「本章摘要 + 核心考点」
    工具式操作入口 无（命令行或平台内嵌） ❌ 缺失 智能体应用层：本地网页，粘贴/上传 → AI 判学科 → 整理 → 一键入库发布
    发布成站点 ✅ 现成且成熟 已满足 直接复用 Obsidian + MkDocs 模板这一层

    核心结论：

    现成方案解决的是"最后一公里"（发布），而我的痛点在"前面九公里"（整理重构）+ "中间的智能决策"（AI）。 我做的事 = 保留成熟的发布层 + 自研学科感知整理层 + 接入本地 AI 智能层，构成一个学科感知的笔记智能体。

    四、我的方案为什么是"个性化"的¶

    不是"功能更多"，而是换个人来用就完全不适用：

    1. 数据个性化：学科档案表里写死的是我的 4 门课（毛概、计网、英语、C 语言），换个专业就得重配。
    2. 流程个性化：每科的处理策略来自我实际的笔记形态（毛概确实是对答、计网确实是算题）。
    3. 痛点个性化：公式上标丢失、# 缺空格，都是我这套笔记特有的损坏模式，通用工具不会去修。
    4. 模型个性化：AI 的学科判断提示词、章节切分与摘要模板，都是针对我的笔记结构定制的；模型跑在我自己的电脑（Ollama）上，笔记数据不出本机。

    五、方案演进：从规则脚本到智能体（v1 → v3）¶

    版本 形态 能力 局限
    v1 规则层
    tools/process_notes.py    		 命令行脚本 学科分流、语法修复、结构重构（纯规则，秒出，零成本） 只能处理"预料之内"的格式；无摘要
    v2 AI 层
    tools/ai_helper.py    		 本地大模型接入 规则 + AI 混合：规则干确定性的 90%，AI 补模糊判断 + 逐章生成「摘要 + 考点」 仍要敲命令，不像"应用"
    v3 智能体应用
    webapp/app.py    		 本地网页应用 粘贴/上传 → AI 自动判学科 → 学科感知整理 → AI 摘要 → 一键入库 → 一键发布 ——（当前版本）

    为什么 v3 才算"智能体"：

    智能体 ≠ 聊天机器人。能"感知输入 → 自主决策 → 执行动作 → 产出结果"的 AI 应用就是智能体： - 感知：读取粘贴的乱笔记 / notes_raw 下的原始文件 - 决策：AI 判断学科 + 规则选择处理策略 + AI 生成章节摘要 - 执行：清洗、按学科重构、写回文件、自动触发站点内容重建 - 产出：docs/ 结构化笔记 → MkDocs 站点自动更新 → git push 上线

    六、系统架构¶

    ┌──────────────────────────────────────────────────┐
│ ① 输入层    粘贴文本 / 上传 .md .txt              │
│     ↓                                             │
│ ② 感知决策  AI 判断学科（Ollama qwen2.5）          │
│     ↓        AI 离线时自动降级 → 关键词规则兜底     │
│ ③ 整理层    通用清洗 → 学科分流（问答/计算/语料/代码）│
│     ↓                                             │
│ ④ AI 增强层 逐章生成「本章摘要 + 核心考点」         │
│     ↓                                             │
│ ⑤ 存储层    notes_raw/*.md（原始笔记库）           │
│     ↓  自动重跑整理                                │
│ ⑥ 发布层    docs/*.md → MkDocs → GitHub Pages     │
└──────────────────────────────────────────────────┘
   全程本地运行；AI 不可用时 ②④ 自动降级，功能不中断

    降级设计是我的一个重点：AI 离线时系统从"智能体"退回"规则工具"，主流程不中断——保证可用性优先。

    七、任务要求达成对照¶

    要求 达成方式 对应交付物
    ① 真实问题 4 门课异构笔记 + 语法损坏 + 无法检索 notes_raw/、README
    ② 检索现成方案 WorkBuddy/豆包/千问 + 6 个 GitHub 项目（重点参考 SuperNote） 本文第二节
    ③ 差异与个性化 逐维度对比 + 四点个性化论证 本文第三、四节
    ④ 魔改 + 本地跑通 在参考方案思路上魔改：规则层 + 新增 AI 层与智能体应用层，本地 python 直接运行 tools/、webapp/、本文第五、六节

    八、演示流程（约 1 分钟）¶

    1. 打开本地智能体 http://127.0.0.1:5000 —— 右上角绿点表示 AI 在线（本地 Ollama）
    2. 粘贴一段乱笔记 → 点「开始整理」→ 展示 AI 判断学科 + AI 摘要生成
    3. 点「存入笔记库」→ 自动写入笔记库并重跑整理
    4. python -m mkdocs serve 打开 http://127.0.0.1:8000/note-website/ —— 笔记已按学科结构化呈现，含 AI 折叠摘要
    5. （可选）git push → GitHub Actions 自动部署线上站点
